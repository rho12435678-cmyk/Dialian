# Dialian · Dial Dev Hub

DDH는 Roblox 개발자가 **포트폴리오를 공유하고 구인·구직으로 연결되는 커뮤니티**입니다.
의뢰와 거래 조건은 이용자들이 DM에서 직접 협의합니다. Dialian은 주문·견적·결제·납품을 처리하지 않습니다.

## 구현된 기능
- 기존에 직접 만든 `운영자` 역할을 승인/문의 권한에 연결하고 중복 `운영진・Staff` 역할은 더 이상 만들지 않음
- 비공개 거래·작품 도용 신고 접수(기존 피드백 티켓 체계 재사용)
- DB 백업 무결성·최신성 점검, 덮어쓰기 없는 복원 테스트, 안내 패널 자동 복구

- 채널·음성 채널·역할·권한을 생성/갱신하는 `/ddh setup`
- 새 유저를 위한 `가이드` 채널의 공식 환영 임베드: 서버 창설 이유, 이용 방법, 구인·구직, 개발자 등록, 안전 수칙
- 가이드 갱신은 서버 소유자의 `/ddh panels`에서 실행
- 소유자의 `/ddh release`에서 배포 버전 공지, GitHub 변경 내역 링크, 선택적 멘션
- 업데이트 공지는 배포한 버전을 자동 감지하여 모든 멤버 역할에 한 번 멘션
- 버전별 중복 방지·재시작 반복 공지 방지 및 DB 저장 실패 후 복구
- 서버 소유자가 실행하는 초기 구성·채널 정리·보안 재설정
- Discord AutoMod: 초대 링크 광고/스팸/과도한 멘션 차단 + 비공개 운영 로그 알림
- 기본 인증 수준 Medium, 멘션만 알림, 모든 멤버 미디어 필터, 채팅 10초 및 구인/포트폴리오 30초 슬로우모드
- 규칙 동의 버튼으로 멤버 역할 지급
- GFX / UI / 복장 / 스크립터 / VFX / 빌더 / 모델러 / 애니메이터의 8개 분야
- 커뮤니티의 질문·아이디어와 거래의 구인·의뢰·포트폴리오를 포럼으로 운영
- 이전 공개 채널은 운영진 전용 Staff 구역에 보존
- 공지·업데이트·문의·파트너 안내를 Discord 공지형식으로 전환 (커뮤니티 기능 필요)
- 공개 문의 카테고리만 안내 바로 아래에 배치하고 티켓·보관은 비공개 운영 구역으로 이동
- 통합 포트폴리오, 제작의뢰, 구인, 채팅, 질문·아이디어 채널
- 파트너 문의 / 서버 피드백 / 개발자 신청 비공개 티켓
- 개발 분야 복수 선택 → 포트폴리오 제출 → 운영진 승인/반려 → 해당 분야 역할 지급
- 파트너 승인 시 파트너 역할 지급 (파트너 소개 게시물은 운영진이 검토 후 직접 게시)
- 소유자가 켠 경우 한국 시간 오후 6시, 기본 2일 간격 이용 안내
- 재시작 후에도 작동하는 패널·티켓 버튼, 중복 티켓/공지 방지
- 처리 중 중단된 티켓 생성·승인·종료 재시도, 운영 로그, 검증된 일일 DB 백업

## DDH 1.0 안정화 및 소유자 역할 안내

- 서버에 **기존 `운영자` 역할이 정확히 하나 있어야 합니다.** Dialian은 이 역할을 내부 운영자 권한에 연결하며, 예전 `운영진・Staff`를 새로 만들거나 자동으로 삭제하지 않습니다. 이름이 중복되면 명시적인 오류로 중단합니다.
- 이전 운영진 역할이 남아 있다면 `/ddh check`에서 확인을 안내합니다. 기존 역할의 멤버·관리 권한 및 비공개 채널 접근을 점검한 다음 서버 소유자가 수동으로 삭제하세요. **자동 삭제 및 자동 권한 상승을 수행하지 않습니다.**
- 새 **거래·도용 신고** 버튼은 `문의-support`에 나타납니다. 진행 중인 피드백/신고 티켓이 있다면 해당 비공개 티켓에 내용을 추가하도록 안내합니다. DDH 운영진은 사실 확인과 서버 정책 적용을 담당하고, DM 결제·작업·환불을 보증하지 않습니다.
- 규칙·공식 가이드·문의 패널이 누락되면 봇 시작 시와 일정 간격으로 **안내 메시지만 복구**합니다. 관리자 요청 없는 채널/역할 대량 변경과 파괴적 정리는 자동 실행하지 않습니다.
- 보안 점검은 기존 Discord AutoMod·감사 로그에 더해 오래된 운영진 역할의 접근, 과도한 운영자 권한, 최근 36시간 백업 및 SQLite 무결성 상태를 검사합니다. 위험 이벤트를 알리되 관리자 계정의 역할·멤버를 자동 추방하거나 무작정 변경하지 않습니다.
- SQLite 백업 사본은 `verify_snapshot`으로 읽기 전용 무결성 검증을 하고, `restore_dry_run`은 별도 파일로 복사해 복구 시험을 합니다. **현재 실행 중인 DB 파일을 덮어쓰지 않습니다.** Discord 메시지·첨부와 서버 전체 권한은 SQLite에 저장되지 않습니다.
- 로컬 Droplet에 보관된 백업만으로는 VPS 장애에 대비할 수 없습니다. 외부 저장소·서버 스냅샷 등의 별도 백업과 복구 계획이 필요하며 이는 서버 소유자가 설정해야 합니다.

## 최초 실행

Python **3.12 이상**이 필요합니다. CI는 3.12에서 실행합니다.

```bash
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows에서는 .venv\Scripts\activate
python -m pip install -r requirements.txt
cp .env.example .env
```

`.env`에 **기존 Dialian 봇 토큰**과 **새 DDH 서버 ID**를 넣습니다.
토큰은 GitHub 코드·Discord 메시지에 붙여넣지 마세요.

```dotenv
TOKEN=봇_토큰
DDH_GUILD_ID=새_DDH_서버_ID
DDH_DATABASE=data/ddh.db
DDH_NOTICE_HOUR=18
DDH_NOTICE_INTERVAL_DAYS=2
```

서버 ID 복사: Discord 설정 → 고급 → 개발자 모드 → DDH 서버 메뉴 → 서버 ID 복사.
설정된 ID와 다른 서버에서는 명령어·버튼·공지·서버 구성이 작동하지 않습니다.
ID가 없거나 잘못된 형식이면 로그인 전에 종료합니다.

### 봇 초대와 권한

Discord Developer Portal의 Dialian 애플리케이션에서 OAuth2 URL Generator를 열고
`bot`, `applications.commands` 범위로 **DDH 서버에 봇을 초대**합니다.

봇 자체 역할에는 다음 권한이 필요합니다.

- 역할 관리, 채널 관리, 채널 보기, 메시지 보내기, 메시지 기록 보기
- **서버 관리(Manage Server)**: Discord AutoMod 규칙 생성·갱신 및 서버 인증 설정에 필요
- 링크 첨부, 파일 첨부, 메시지 관리
- 멤버 타임아웃, 멤버 음소거, 멤버 헤드셋 음소거, 멤버 이동
- 연결, 말하기

역할 지급에 필요한 경우 Dialian 역할은 지급할 멤버·개발자·분야 역할 위에 두세요.
운영진·관리자와 소유자 표시용 역할의 순서는 Discord 서버 설정에서 직접 정합니다.
초기 구성은 기존 역할 순서를 편집하지 않습니다.
봇에 **감사 로그 보기**, **스레드 관리**, **멤버 추방 및 차단** 권한도 부여합니다.
입퇴장 로그를 사용하려면 Discord Developer Portal → Dialian → Bot에서 **Server Members Intent**를 켠 뒤 봇을 재시작하세요.
이 인텐트가 꺼져 있으면 봇은 나머지 기능으로 연결하고 `/ddh check`에 입퇴장 로그가 꺼졌다고 표시합니다.
메시지 내용 인텐트는 사용하지 않습니다.
이 구현은 메시지 내용을 읽는 `!명령어` 대신 슬래시 명령어를 사용합니다.

```bash
python dial.py --check-config  # 설정만 검증; Discord 접속 없음
python dial.py
```

1. 소유자가 `/ddh setup`으로 초기 항목을 확인합니다.
2. 새 서버는 `/ddh setup apply:True`로 누락된 항목과 최초 안내 패널을 생성합니다.
3. 기존 서버의 가이드·질문·아이디어·자료 채널은 `/ddh layout`에서 미리 보고 `/ddh layout apply:True`로 한 번 적용합니다.
4. AutoMod를 설정할 때는 소유자가 `/ddh security`를 실행합니다.

초기 구성은 기존 역할·카테고리·채널을 ID나 이름으로 연결하고 빠진 항목만 생성합니다.
재시작이나 재연결에는 채널·역할·보안 재구성 및 가이드·업데이트 자동 게시가 없습니다.
기존 `DDH_AUTO_SETUP`, `DDH_NOTICES_ENABLED` 값은 적용하지 않습니다.

## 미니멀 한글·영어 병기 채널 구성

| 공개 카테고리 | 채널 |
|---|---|
| 📌 안내・Info | 공지-news, 업데이트-updates, 규칙-rules, 가이드-guide (공지) |
| 📨 문의・Support | 문의-support, 파트너-partners (모두 Discord 공지 채널) |
| 💬 커뮤니티・Chat | 채팅-chat, 사진-pics, 질문-question (포럼), 아이디어-ideas (포럼) |
| 💼 거래・Market | 구인-hiring (포럼), 의뢰-commissions (포럼), 포트폴리오-portfolio (포럼) |
| 🔊 음성・Voice | 라운지-voice, 작업-work |

**🔒 운영・Staff**에 운영진-chat, 읽기 전용 로그-logs·보안-security와 진행 중인 비공개 문의를 둡니다.
채널 정리 명령은 중복 질문·아이디어 텍스트 채널을 Staff에 보존하고 기존 자료 채널과 자료 보관본을 영구 삭제합니다.
문의가 종료되면 처리 결과는 DB와 운영 로그에 기록한 뒤 대화 채널을 삭제합니다.
**관리자・Admin** 역할은 운영진・Staff 바로 아래, 개발자・Developer 바로 위입니다.

### 공지 순서·규칙 및 서버 가이드

- 📌 안내 카테고리 맨 위에 공지-news → 업데이트-updates를 배치하고 규칙-rules, 가이드-guide를 이어서 배치합니다.
- Discord 커뮤니티의 규칙 채널(rules_channel)을 DDH 규칙-rules로 연결합니다. 상단 체크 표시 rules는 Discord 서버의 규칙/서버 가이드 기능입니다.
- **규칙과 가이드를 위쪽의 두 리소스 페이지로 표시하는 최종 단계는 Discord UI에서 수동 설정해야 합니다.** 서버 설정 → 온보딩(Onboarding) → 서버 가이드(Server Guide) → 리소스(Resources)에서 규칙-rules와 가이드-guide를 추가하세요. 등록된 읽기 전용 채널은 일반 채널 목록에서 숨겨지고 가이드 리소스로 보여집니다.
- 봇은 규칙 동의 버튼과 DDH 신규 유저 가이드 임베드를 계속 갱신합니다.

### 이전 보관·티켓 카테고리 영구 정리

- **주의: Discord 채널 삭제는 되돌릴 수 없으며 SQLite 백업에는 Discord 대화·첨부파일이 포함되지 않습니다.**
- 과거 티켓·보관 카테고리는 신규 레이아웃에서 생성하지 않습니다. 기존 기록은 자동으로 파괴하지 않습니다.
- 서버 소유자가 `/ddh cleanup`으로 대상 카테고리 및 삭제 채널 수를 미리 확인하고, 기록 삭제를 선택한다면 `/ddh cleanup confirm:True`로 영구 정리합니다.
- 진행 중인 문의는 운영・Staff 카테고리로 옮겨 보존합니다. 새 문의도 운영진·신청자만 볼 수 있는 운영 카테고리에 생성합니다. 종료된 문의 채널은 DB에 결과를 기록한 뒤 삭제합니다.
- 오래된 포트폴리오·채팅·보관 게시물은 삭제 전 필요한 내용이 없는지 점검해야 합니다.
- 공지-news, 업데이트-updates, 문의-support, 파트너-partners는 Community 서버의 공지 채널로 운영합니다.
### 권한 정책

| 역할 | 열람 | 작성·음성 | 비공개 문의 |
|---|---|---|---|
| 방문자 | 공개 채널 | 규칙 동의 전 채팅·음성 이용 불가 | 없음 |
| 멤버 | 공개 채널 | 채팅·구인·의뢰·공개 음성 | 본인의 진행 중 티켓 |
| 개발자 | 공개 채널 | 멤버 권한 + 통합 포트폴리오 글쓰기 | 본인의 진행 중 티켓 |
| 분야 역할 | 공개 채널 | 분야 인증(포트폴리오 태그로 구분) | 본인의 진행 중 티켓 |
| 파트너 | 공개 채널 | 멤버와 동일; 운영 권한 없음 | 본인의 진행 중 티켓 |
| 운영진・Staff | 모든 관리 대상 채널 | 심사·메시지 관리·타임아웃·음성 관리 | 진행 중 문의 |
| 관리자・Admin | 모든 관리 대상 채널 | 서버·채널·역할 관리, 강퇴·차단, 운영진 업무 | 진행 중 문의 |

서버 소유자와 Discord 관리자 권한 보유자는 Discord의 관리자 권한으로 모든 채널에 접근할 수 있습니다.
서버 구성을 변경하는 명령은 실제 Discord 서버 소유자만 실행할 수 있습니다. DDH 관리자에게는 서버·채널·역할 관리 권한을 주지만 전역 Administrator 권한은 부여하지 않으며, 소유자가 믿을 수 있는 사람에게만 역할을 직접 지정해야 합니다. 운영진에게는 역할/채널 관리 권한을 주지 않습니다.
규칙 동의·승인으로 지급하는 역할에 관리 권한이 추가되어 있으면 역할 지급을 중단합니다.

소유자는 Discord에서 채널과 역할의 이름, 순서, 권한을 직접 정할 수 있습니다.
`/ddh check`는 점검 결과를 표시하며 서버 설정을 변경하지 않습니다.

## 처음 방문한 멤버를 위한 DDH 공식 가이드

- DDH는 기존 DDS의 직접 디자인 주문제작 중심 방식에서 확장된 **Roblox 개발자 포트폴리오·협업·구인·구직 허브**입니다.
- 봇은 `📌 안내` 카테고리의 `가이드` 채널에 DDH 창설 취지·8개 개발 분야·채널 사용법·4단계 참여 절차·안전 수칙을 소개하는 **보라색 임베드**를 게시합니다.
- 안내문에는 규칙·채팅·질문·문의·구인·제작의뢰·통합 포트폴리오·업데이트 채널을 실제 디스코드 채널 멘션으로 연결합니다.
- 기존 가이드 채널은 ID와 이름을 유지하고 `/ddh layout`에서 공지 형식으로 전환합니다.
- 최초 구성에서 가이드를 게시합니다. 이후 소유자가 `/ddh panels`를 실행하면 안내문을 갱신합니다.
- 글을 갱신할 때 `DDH:guide:v1` 메시지 표식을 유지하여 중복 게시를 방지합니다. 가이드를 새로 작성할 때 멤버 전체 멘션을 보내지 않습니다.

## 문의·심사 흐름

- 규칙 동의 후 문의 종류를 선택합니다.
- 개발자 신청에서는 분야를 복수 선택하고 Roblox 사용자명, 포트폴리오 링크, 작업 경력·담당 부분을 작성합니다.
- 신청자·운영진·봇만 보는 텍스트 채널이 생성됩니다. 같은 종류의 진행 중 티켓은 1개, 새 생성은 1분에 1회입니다.
- 운영진은 **승인/반려 버튼 → 처리 사유 입력**으로 결정합니다. 일반 개발자/파트너/신청자는 심사할 수 없습니다.
- 개발자 승인: 멤버 + 개발자 + 선택한 분야 역할. 파트너 승인: 멤버 + 파트너.
- 피드백은 승인/반려 없이 대화 후 종료합니다. 종료는 신청자 또는 운영진만 가능합니다.
- 종료하면 신청자 접근을 제거한 뒤 티켓 채널을 삭제합니다. 신청서·심사·종료 정보는 DB에 남습니다.
- 신청 정보와 심사 상태는 SQLite, 대화·첨부 파일은 Discord 채널에 남습니다.
- 승인 이후 역할 회수는 운영진이 Discord에서 직접 처리합니다. 승인된 역할을 재시작 때 자동으로 재지급하지 않습니다.

신청 화면(분야 선택 5분, 입력 10분)은 일시적이므로 재시작 후 다시 열어야 할 수 있습니다.
이미 게시된 규칙·문의·티켓 관리 버튼은 재시작 후에도 작동합니다.
DB 저장 직전 연결이 끊겨도 채널 topic의 티켓 ID로 기존 티켓을 찾아 복구합니다.
역할 지급 전에 승인 의사를 기록하므로 일부 역할만 지급된 채 중단되어도 자동으로 재시도합니다.
승인 중에는 반려/종료를 막습니다. 봇 권한·역할 순서를 복구하면 승인 작업이 이어집니다.

## 명령어와 공지

| 명령어 | 사용자 | 동작 |
|---|---|---|
| `/ddh plan` | 관리자 | 구성표 미리보기 |
| `/ddh setup` | 소유자 | 초기 구성 미리보기 |
| `/ddh setup apply:True` | 소유자 | 빠진 초기 역할·채널 생성 |
| `/ddh layout` | 소유자 | 가이드·질문·아이디어·자료 정리 미리보기 |
| `/ddh layout apply:True` | 소유자 | 포럼 정리와 자료 채널 영구 삭제 |
| `/ddh panels` | 소유자 | 안내 패널 복구 또는 문구 갱신 |
| `/ddh check` | 관리자 | 역할·채널·AutoMod·입퇴장 설정 점검 |
| `/ddh verify member:…` | 소유자 | 계정 나이 예외 수동 인증 |
| `/ddh security` | 소유자 | DDH AutoMod·인증·알림·콘텐츠 필터 재설정 |
| `/ddh release` | 소유자 | 배포 버전 공지 게시 |
| `/ddh notices enabled:True/False` | 소유자 | 정기 안내 켜기 또는 끄기 |
| `/ddh status` | 누구나 | 연결·구성·공지 상태 |

정기 안내는 기본적으로 꺼져 있습니다. 소유자가 켜면 최초 구성 날짜를 기준으로
기본 2일 간격, 한국 시간 18시에 공지사항에 게시합니다.

### DDH 보안 적용 범위

- DDH 접두어가 붙은 Discord AutoMod 규칙만 생성/수정합니다. 운영자가 별도로 만든 규칙을 삭제·덮어쓰지 않습니다.
- 다른 서버 초대 링크(`discord.gg/`, Discord invite URL)는 일반 메시지에서 차단합니다. 파트너 문의는 비공개 **신청 모달**로 제출할 수 있고 승인된 파트너 홍보는 운영진이 게시합니다.
- 스팸 콘텐츠와 메시지당 5회 초과 멘션을 Discord AutoMod가 차단하며, 감지된 내용은 보안-security 채널로 알립니다. 슬로우모드가 빠른 반복 발화를 추가로 제한합니다.
- 기존의 Discord 스팸/멘션 규칙이 있으면 중복 생성하지 않고 기존 규칙을 보존합니다. Discord 규칙 개수 제한 또는 권한 문제로 설치가 실패하면 로그를 확인하고 다시 적용합니다.
- Medium 인증 수준, 모든 멤버의 미디어 콘텐츠 필터, 기본 알림은 멘션만 적용합니다.
- 이 보호 기능은 일반 멤버의 도배·초대 광고·멘션 공격을 줄이지만 **관리자 계정 탈취·악성 관리자의 채널 삭제를 사전에 완전히 막거나 자동 복원하지는 못합니다**. 관리자 권한을 최소화하고 Discord 보안/2FA 및 외부 백업을 유지하세요.

## 자동 업데이트 공지 · Discord 전용 게시

- 소스 배포 상태는 내부적으로만 확인합니다. 배포가 완료된 새 버전마다 `업데이트-updates` 채널에 임베드 하나를 자동 게시하고 멤버 역할을 멘션합니다. 별도의 명령어·신청 버튼이 없습니다.
- **Discord 게시물에는 소스 저장소 URL, GitHub 계정, 커밋 SHA, 작성자 이름, 커밋 메시지 등 개발 저장소를 식별할 정보를 넣지 않습니다.**
- 공식 임베드는 주황색 브랜드 색상, 변경 기능의 범주, 적용 완료 여부 및 시각만 제공합니다. 변경 파일의 이름은 외부에 보여주지 않고, 코드 변경 범주에 따라 안전한 한국어 요약으로 전환합니다.
- 상세 공지 문구가 필요한 경우 서버 내부의 Git 비추적 경로 `data/release-notes/<배포 SHA>.txt`에 별도로 저장할 수 있습니다. 실제 공지 문구는 DigitalOcean 서버에만 존재하며 소스 저장소에는 포함되지 않습니다. 이 파일이 없으면 자동으로 변경 범주를 요약합니다.
- 임베드와 메시지의 맨 위에 `@멤버・Member`를 표시합니다. 실제 멘션 알림은 메시지 본문에 있는 역할 멘션으로 전송합니다.
- SQLite에 이전 배포 상태를 저장하고, Discord에서는 **저장소와 연결되지 않은 임의의 공지 식별자**를 사용해 중복을 방지합니다. 기존 공지도 안전하게 식별하여 재게시를 막습니다.
- 이전 업데이트 알림 신청·해제 패널은 자동 제거하고 다른 공지 메시지는 유지합니다. 개인별 Discord 알림 설정에 따라 푸시 알림이 제한될 수 있습니다.
- 새로운 소스 코드가 DigitalOcean에서 실행되어야 공지가 게시됩니다. 단순히 원격 소스에 변경사항이 올라간 것만으로는 Discord 메시지가 발송되지 않습니다.
## 기존 DDS 기능 정리

다음 기능과 관련 코드·테스트·종속성을 제거했습니다.

- GFX·복장·UI 주문, 가격표·묶음·할인, 디자이너 선택·배정, 계좌·결제 안내
- 진행률·납기·작업 완료·구매자 역할, 구매 후기·별점·매출·디자이너 통계
- 출석·포인트·랭킹·단골, 미니게임·포인트 베팅, FAMILY 유료 구독
- DDS 판매·출시·업데이트 공지와 하드코딩된 DDS 채널/역할/서버 ID
- 개인 DM 거래 차단, 강제 Roblox 착용 아이템 가격 인증, 자동 닉네임 변경
- OpenAI 자동 번역과 번역 API 설정, 채팅에서 원격 git 업데이트/재시작 명령

기존 `data/dialian.db` 및 `database/database.db`, 서버의 과거 티켓·메시지를 삭제하거나 변환하지 않습니다.
새 DB 기본 경로는 `data/ddh.db`입니다. DDS 테이블이 들어 있는 파일을 지정하면 열람 점검 후 초기화를 거부합니다.
기존 소스는 Git 이력에 남습니다. 과거 거래 기록은 필요 시 별도로 보관/열람하세요.

## 기존 VPS에서 재가동

기존 저장소에 있던 `/root/Dialian` 경로와 `HOST`, `USERNAME`, `SSH_PRIVATE_KEY`, `TOKEN` GitHub Secrets를 재사용합니다.
자동 `main` 푸시 배포는 **수동 실행 Deploy DDH Bot**으로 바꿨습니다.
DDH 서버 ID를 확인하기 전에 기존 DDS 봇을 자동으로 교체하지 않기 위한 전환 절차입니다.

1. 이 변경을 검토하고 병합합니다.
2. 봇을 DDH에 초대하고 역할 순서·권한을 설정합니다.
3. GitHub Actions → **Deploy DDH Bot** → Run workflow → `ddh_guild_id`에 새 서버 ID를 입력합니다.
4. 선택한 커밋의 테스트가 통과하면 기존 VPS에서 해당 커밋을 받아 검증합니다.
5. Discord 로그인·대상 서버 권한 확인이 통과한 뒤 기존 `nohup` 실행을 종료하고 systemd 서비스로 전환합니다.
6. Discord에서 `/ddh setup apply:True`를 실행합니다.

VPS에는 Python 3.12+, `python3-venv`, Git, systemd와 `/root/Dialian` 접근 권한이 필요합니다.
로컬 소스 변경이 있으면 덮어쓰지 않고 배포를 중단합니다. 별도로 보관/커밋한 후 다시 실행하세요.
`venv-ddh/`에 전용 환경을 만들고 `.env.ddh`(권한 600)에 서비스 환경을 저장합니다.
봇은 서버 재부팅·비정상 종료 시 systemd가 재시작합니다. **동일 봇을 두 프로세스로 실행하지 마세요.**

```bash
systemctl status dialian.service
journalctl -u dialian.service -n 100 --no-pager
systemctl restart dialian.service
```

배포 검증은 대상 서버 로그인과 Gateway 연결까지 확인합니다. 서버 구성·티켓 실제 조작 확인은 별도입니다.
배포 실패 시 Actions 로그와 systemd 로그를 확인하세요. 소스 checkout은 바뀌었을 수 있으므로,
구버전으로 되돌릴 때는 서비스를 중지하고 원하는 이전 커밋으로 checkout한 뒤 기존 가상환경/설정으로 실행해야 합니다.

## 입퇴장 기록과 운영 점검

- 입퇴장과 인증·티켓 처리 기록은 로그-logs에 표시합니다. 역할 권한·채널 삭제·웹훅·서버 설정 등 주요 Discord 감사 이벤트는 보안-security에서 확인합니다. 표시되는 로그에는 시각, 대상 ID, 감사 이벤트에 있는 실행자 ID를 사용합니다.
- 로그를 DB에 먼저 기록하고 전송 실패 또는 로그 채널 권한 불일치 시 재시도합니다. Discord 감사 로그는 Gateway 이벤트와 별도로 주기적으로 조회합니다. 봇이 연결되지 않았을 때의 일반 입퇴장 이벤트는 복구할 수 없습니다.
- 최근 60초간 5명 이상 입장하거나 주요 관리 변경이 4건 이상 발생하면 운영진에 경보를 기록합니다. 관리 대상 역할·채널 권한과 AutoMod도 5분마다 확인합니다. 경보는 운영진이 검토하며 자동 제재는 적용하지 않습니다.
- 신규 사용자는 Discord 규칙 확인을 마치고 규칙-rules의 인증 버튼을 누릅니다. 자동 인증 계정 나이 기준은 기본 7일(`DDH_VERIFY_MIN_DAYS`)이며, 서버 소유자는 계정 나이 예외를 검토해 수동 인증할 수 있습니다. 이미 멤버 역할을 가진 사용자는 그대로 이용합니다.
- 성공적으로 전송된 운영 로그 레코드는 30일 후 SQLite에서 정리합니다. Discord에 게시된 기록의 보존 기간은 별도입니다.

## 데이터와 백업

프로세스 시작 시와 이후 매일 UTC 날짜가 바뀐 후 한 번 `data/ddh-backups/`에 SQLite 백업을 만듭니다.
백업의 무결성과 필수 테이블을 확인한 뒤 14일 초과 백업만 정리합니다. 기존 DDS 백업에는 손대지 않습니다.
DB·백업·환경 파일·로그는 Git에 포함하지 않습니다. 복구 시 먼저 서비스를 중지하고
검증된 백업을 `data/ddh.db`에 복사하며 이전 `ddh.db-wal`, `ddh.db-shm`은 함께 별도 보관하세요.
