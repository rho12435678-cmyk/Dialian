# Dialian

Discord 티켓 및 커미션 관리 봇입니다.

## 설치

```powershell
python -m pip install -r requirements.txt
```

프로젝트 최상단에 `.env` 파일을 만들고 값을 설정합니다.

```env
TOKEN=디스코드_봇_토큰
OPENAI_API_KEY=OpenAI_API_키
TRANSLATION_CHANNEL_ID=번역을_실행할_채널_ID
```

`OPENAI_API_KEY`는 선택 사항입니다. 설정하지 않아도 봇은 실행되며, 자동 번역 기능만 비활성화됩니다. `TRANSLATION_CHANNEL_ID`를 설정하면 해당 채널에서만 자동 번역이 실행됩니다.

## 실행

```powershell
python dial.py
```

이 컴퓨터에 준비된 가상환경(프로젝트 전용 Python)을 사용하려면 다음으로 실행합니다.

```powershell
.\.venv\Scripts\python.exe dial.py
```

## 주요 명령어

- `!명령어`, `!도움말`, `!help`: 명령어 목록 표시
- `!티켓생성`: 티켓 생성 패널 전송
- `!계좌전송`, `!티켓닫기`, `!티켓삭제`: 기존 티켓 복구용 명령어
- `!진행 0|25|50|75|100`, `!예상 1일|2일|3일`, `!완료`: 작업 진행 관리
- `!재시작`, `!봇재시작`, `!restart`: 관리자 전용 봇 재시작

일부 명령어는 관리자 또는 담당 디자이너 권한이 필요합니다.

재시작은 안내 메시지 전송 후 Discord 연결과 백그라운드 작업을 종료하고, 같은 Python 실행 환경과 인자로 봇을 다시 실행합니다.
일반 종료(`Ctrl+C`)나 로그인 실패에는 자동 재시작하지 않습니다. 최신 코드를 내려받으려면 `!업데이트` 후 `!재시작`을 실행하세요.
재시작 후 `!봇상태`에서 시작 시간을 확인할 수 있습니다. 이 명령을 처음 추가할 때는 서버에 코드를 반영하고 기존 방식으로 한 번 재시작해야 합니다.

## 로블록스 인증

1. `config.py`의 `CUSTOMER_ROLE_ID`를 인증 후 지급할 역할 ID로 설정합니다.
2. 봇에 **별명 관리**, **역할 관리** 권한을 주고 봇 역할을 인증 대상자와 손님 역할보다 위에 놓습니다.
3. 봇을 재시작한 뒤 관리자가 인증 채널에서 `!인증패널`을 입력합니다.
4. 사용자는 **로블록스 인증하기**에서 `@사용자이름`을 입력하고, 프로필 소개(About)에 일회용 코드를 추가한 뒤 **인증 확인**을 누릅니다.

인증 후 서버 닉네임은 로블록스 **사용자이름**으로 설정됩니다(표시 이름과 다르며 `@`는 붙이지 않습니다).
인증 안내와 오류는 본인에게만 표시됩니다. 비밀번호, 쿠키, 로블록스 API 키는 필요하지 않습니다.
코드는 10분 후 만료되며 인증 후 소개란에서 삭제해도 됩니다. 새 코드 발급 시 이전 코드는 무효가 됩니다.
동일 서버에서 하나의 로블록스 계정을 여러 디스코드 계정에 연결할 수 없습니다.
인증 정보와 진행 중인 코드는 `data/dialian.db`에 저장되어 재시작 후에도 유지됩니다.
기존 회원은 `!인증업데이트` 또는 패널의 **인증 정보 업데이트** 버튼으로 닉네임과 손님 역할을 갱신합니다.
연결된 계정은 아래 조건을 다시 검사하며, 아직 로블록스 계정을 연결하지 않은 회원에게는 최초 인증을 안내합니다.
기존 패널의 **닉네임 동기화** 버튼도 업데이트 기능으로 동작합니다. 새 버튼 이름과 조건 안내를 표시하려면 관리자가 `!인증패널`을 다시 실행하세요.
서버 소유자의 닉네임은 봇이 수정할 수 없으므로 다른 계정으로 테스트하세요.
기존 손님 역할을 자동 회수하지는 않습니다. 기존 사용자도 계정 연결을 위해 새 인증을 진행해야 합니다.

### 인증 조건

- 로블록스 계정 생성 시각부터 **30일(30 × 24시간) 이상** 경과해야 합니다.
- **현재 착용 중인 아이템의 현재 판매가 합계가 5로벅 이상**이어야 합니다. 같은 아이템은 한 번만 합산합니다.
- 무료 아이템, 판매가 없는 아이템, 재판매도 중단된 아이템, 번들 전용 구성품은 합산하지 않습니다. 판매 중인 리미티드는 조회 가능한 최저 판매가를 사용합니다.
- 가격은 Roblox API의 현재 공개 판매가이며 실제 지출액·구매 이력을 증명하지 않습니다. 무료로 얻었다가 유료화된 아이템 등도 현재 판매가로 계산되므로 부계를 완전히 차단하는 수단은 아닙니다.
- API 오류나 생성일·착용 정보 조회 실패 시 인증 또는 업데이트를 통과시키지 않습니다.
- 신규 인증, 최종 코드 확인, 기존 인증 정보 업데이트 모두 같은 조건을 검사합니다. 기존 회원의 역할을 일괄 회수하거나 자동 강퇴하지 않습니다.

기준은 `database/services/roblox_verification.py`의 `MIN_ACCOUNT_AGE_DAYS`, `MIN_AVATAR_ROBUX`에서 변경할 수 있습니다.
계정과 가격 정보는 [Roblox Users API](https://create.roblox.com/docs/cloud/reference/features/users)와 [Catalog API](https://catalog.roblox.com/docs/json/v1)를 사용합니다.

## DDS 티켓 자동 정리 및 후기 포인트

새로 생성되는 GFX·복장·개발자 지원·파트너 문의 티켓은 서버 사이드바의
전용 비공개 카테고리(상단)에 배치됩니다. 이름에는 분야, 배정된 담당자의
GFX 등급(해당하는 경우), 담당자의 Discord 닉네임, 신청자 닉네임이
표시됩니다. 담당자를 나중에 배정하면 이름도 변경됩니다. 기존 진행
티켓은 관리자가 `!티켓정리`를 실행하면 보관된 티켓은 건드리지 않고
정리됩니다. 단품·2+1·3+1 복장 신청서에는 Roblox 닉네임 입력란이
있으며 묶음은 작품 순서별 닉네임을 쉼표로 나눠 작성할 수 있습니다.

> Discord의 Browse Channels 체크/선택 상태는 사용자 개인 설정이므로
> 봇이 강제로 변경할 수 없습니다. 대신 신규 티켓의 직접 링크를 신청
> 완료 화면과 DM으로 전달합니다(DM 차단 시 완료 화면의 링크 이용).

모든 포인트 변동은 등록된 TOP 10 패널을 즉시 갱신합니다. 패널은 3분마다
한 번 더 재동기화됩니다. 새 별점 후기는 별도 지급 기록에 저장하며,
후기 게시 후 포인트 처리 중 오류가 나면 `pending` 상태를 3분 간격으로
자동 재시도합니다. 같은 후기에는 중복 지급되지 않습니다.

구버전 2026년 9월 후기에는 **기존 포인트 지급 성공 여부를 증명하는
기록이 없습니다**. 따라서 과거 후기를 자동으로 다시 지급하는 것은
중복 지급 위험이 있습니다. 관리자는 `!후기포인트점검`으로 DB 기록과
후기 채널 게시물 수를 확인하고, 후기 게시물 및 기존 적립 내역을
대조해 **실제 누락이 확인된 건에 한해** 다음을 실행합니다:

- `!후기포인트복구 <티켓ID> 단품`
- `!후기포인트복구 <티켓ID> 2+1`
- `!후기포인트복구 <티켓ID> 3+1`

개별 복구 명령어도 보안실 전용이며, 승인 관리자 ID가 기록됩니다. 복구 전 관리자 점검 화면에서 구버전 `database/database.db` 포인트 파일의 존재 여부도 읽기 전용으로 확인할 수 있습니다. 기존 DB와 새 DB의 점수를 무조건 합산하지 마세요.

개별 복구에는 승인 관리자 ID가 기록되며, 두 번 실행해도 중복 적립되지
않습니다. 정상 패널이 없으면 랭킹 채널에서 `!포인트랭킹`을 실행한
다음 `!랭킹갱신`을 실행하세요.

## 데이터 및 보안

- `.env`, SQLite DB, 백업 파일, 배포 백업 파일은 Git에 포함하지 않습니다.
- 계좌 정보와 티켓 기록은 `data/dialian.db`에 저장됩니다.
- DB는 시작 시와 이후 24시간마다 `data/backups/`에 백업하며, 14일이 지난 백업은 정리합니다.
- 자동 번역 전송 전 이메일, 전화번호, 긴 숫자 형식의 식별 정보는 마스킹합니다.
- GitHub 배포 Secrets에는 `HOST`, `USERNAME`, `SSH_PRIVATE_KEY`, `TOKEN`이 필요하며 자동 번역 사용 시 `OPENAI_API_KEY`도 추가해야 합니다.
